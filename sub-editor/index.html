Output (Gauge / Wired Display)
The needle eases toward a new reading over roughly this many seconds instead of snapping to it every update - real analog needles have inertia. 0 disables smoothing for a gauge that should react instantly.
Makes the needle shiver around its Value Binding position at a rate read from a second binding (e.g. sonar.pulse_hz) - one gauge shows both an amplitude (where it points) and a frequency (how fast it shivers) at once. Speed Scale shrinks the real Hz value for the animation - a raw 0.5-3 Hz sonar pulse rate would otherwise be too fast to read as a rate by eye; lower this further if it's still too quick to perceive.
Shows the normal texture (above) when off, this one when the bound value is true/on.

Input Binding
Binding above fires when turning the switch ON. State Binding is the live boolean that says which state is currently active.
On: sends the Binding above with Payload Key set to true/false (e.g. SET_ELECTRIC_MOTOR / active) - just the one action to fill in. Off: for two separate actions instead (e.g. START_ENGINE / STOP_ENGINE), fill in the OFF Binding below too.

OFF
Rotation is added on top of the object's own Rotation, per state - e.g. reuse the same "up" sprite for OFF and give ON a Rotation of 180° instead of needing a second, flipped texture.
The JSON key this control's value is sent under - almost always "value"; picking a known Binding above fills this in automatically when it needs something else (e.g. SET_GEAR expects "gear").
For an action needing a SECOND fixed field alongside the control's own value - e.g. SET_TUBE_ARMED needs {tube: 0, armed: true|false}: Payload Key = armed (the control's own on/off), Extra Payload Key = tube, Extra Payload Value = 0 (fixed per instance - arm tube 1 with a different object per tube, each with its own Extra Payload Value). Leave Extra Payload Key blank for anything that only needs the one Payload Key above. A number-looking value is sent as a number, otherwise as a string.
